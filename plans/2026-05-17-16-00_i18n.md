# Plan: Localización con react-i18next

## Motivación

El texto de la interfaz está actualmente en línea en el JSX, en español. Extraerlo a un
catálogo de traducciones permite:

1. Añadir inglés (u otro idioma) sin tocar el código de los componentes.
2. Revisar o corregir textos en un solo sitio.
3. Aprovechar herramientas de gestión de traducciones si el proyecto crece.

La elección de **react-i18next** frente a alternativas más simples se justifica por el
volumen de cadenas (62), la presencia de cadenas interpoladas (`{{count}} marcados`) y
la necesidad de detección automática del idioma del navegador.

---

## Paquetes

```bash
npm install react-i18next i18next i18next-browser-languagedetector
```

| Paquete | Por qué |
|---|---|
| `i18next` | Motor core: carga namespaces, interpola, resuelve fallbacks |
| `react-i18next` | Hooks (`useTranslation`) y provider para React |
| `i18next-browser-languagedetector` | Detecta el idioma en `navigator.language` y lo persiste en `localStorage` |

No se añade ningún plugin de carga de ficheros: los JSON de locale se importan
estáticamente (Vite los convierte a chunks del bundle, sin petición de red adicional).

---

## Estructura de ficheros resultante

```
src/
├── i18n/
│   ├── index.ts          ← inicialización de i18next (importado en main.tsx)
│   ├── types.ts          ← augmentación de módulo para tipado de claves
│   └── locales/
│       ├── es.json       ← fuente de verdad (español)
│       └── en.json       ← traducciones al inglés
```

## Inicialización (`src/i18n/index.ts`)

```ts
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import LanguageDetector from 'i18next-browser-languagedetector'
import es from './locales/es.json'
import en from './locales/en.json'

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: { es: { translation: es }, en: { translation: en } },
    fallbackLng: 'es',
    interpolation: { escapeValue: false },  // React ya escapa
    detection: {
      order: ['localStorage', 'navigator'],
      caches: ['localStorage'],
    },
  })

export default i18n
```

Importar en `main.tsx` antes del render:
```ts
import './i18n'   // efecto de inicialización
```

## Tipado de claves (`src/i18n/types.ts`)

Con la augmentación de módulo de react-i18next, TypeScript infiere las claves del JSON
de español y marca como error cualquier clave inexistente o mal escrita:

```ts
import type es from './locales/es.json'

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'translation'
    resources: { translation: typeof es }
  }
}
```

Así `t('annotationTool.undo')` compila; `t('annotationTool.undoo')` no.

Tres cadenas → `t('videoLoader.dragPrompt')`, etc.

### `src/components/FramePicker.tsx`
Tres cadenas → `t('framePicker.hint')`, `.back`, `.capture`.

### `src/components/AnnotationTool.tsx`
- Cadenas simples → `t('annotationTool.*')`.
- Cadenas con interpolación:
  ```tsx
  t('annotationTool.markedCount', { done: points.length, total: COURT_KEYPOINTS.length })
  t('annotationTool.allMarked',   { done: points.length, total: COURT_KEYPOINTS.length })
  ```
- La cadena `hintOutOfFrame` contiene HTML (`<strong>`). Usar
  `dangerouslySetInnerHTML` o dividirla en dos partes literales para evitarlo.
  Se recomienda dividirla:
  ```tsx
  // es.json
  "hintOutOfFrame": "Esquina fuera del encuadre: activa"
  "hintOutOfFrameBtn": "⤢ Fuera de frame"
  // JSX
  <span>{t('annotationTool.hintOutOfFrame')} <strong>{t('annotationTool.outOfFrameBtn')}</strong></span>
  ```

### `src/components/AnnotationCanvas.tsx`
`PHASE_INSTRUCTIONS` pasa a ser un array derivado de `t` dentro del componente:
```tsx
const { t } = useTranslation()
const PHASE_INSTRUCTIONS = [
  t('annotationCanvas.phase0'),
  t('annotationCanvas.phase1'),
  t('annotationCanvas.phase2'),
  t('annotationCanvas.phase3'),
]
```
La cadena de `angleWarning` → `t('annotationCanvas.parallelWarning')`.

### `src/components/CourtDiagram.tsx`
Dos cadenas → `t('courtDiagram.title')`, `t('courtDiagram.imaginary')`.

### `src/components/ValidationView.tsx`
- Cadenas simples → `t('validationView.*')`.
- Cadenas con interpolación:
  ```tsx
  t('validationView.qualityExcellent', { cm })
  t('validationView.qualityAcceptable', { cm })
  t('validationView.qualityPoor', { cm })
  ```

### `src/lib/courtKeypoints.ts`
Los labels de los keypoints (en el array `DEFS`) dejan de ser cadenas estáticas.
Dos opciones:

**Opción A — IDs como claves de traducción (recomendada):**
El array `DEFS` almacena una clave de i18n en lugar del label ya traducido:
```ts
const DEFS: Omit<CourtKeypoint, 'color' | 'label'>[] & { labelKey: string }[] = [
  { id: 'A', labelKey: 'courtKeypoints.A', real: { x: 0,  y: 0  } },
  // ...
]
```
Los componentes que muestran el label llaman a `t(kp.labelKey)`. El tipo
`CourtKeypoint` cambia `label: string` por `labelKey: string`.

**Opción B — label resuelto en inicialización:**
Mantener `label: string` en el tipo pero poblarlo mediante `i18n.t()` en tiempo
de ejecución al arrancar. Más simple para los componentes, pero requiere que los
labels se regeneren cuando el usuario cambia de idioma (añadir listener
`i18n.on('languageChanged', ...)`).

Se recomienda la **Opción A** por ser puramente reactiva y sin efectos secundarios.

## Selector de idioma (opcional)

Un componente `LanguageSwitcher` mínimo en el header de `App.tsx`:
```tsx
import { useTranslation } from 'react-i18next'

export function LanguageSwitcher() {
  const { i18n } = useTranslation()
  return (
    <button onClick={() => i18n.changeLanguage(i18n.language === 'es' ? 'en' : 'es')}>
      {i18n.language === 'es' ? 'EN' : 'ES'}
    </button>
  )
}
```
El cambio de idioma es inmediato: react-i18next notifica a todos los componentes y
éstos se re-renderizan con los nuevos textos.

## Fases de implementación

### Fase 1 — Scaffolding (½ h)
1. `npm install react-i18next i18next i18next-browser-languagedetector`
2. Crear `src/i18n/index.ts` y `src/i18n/types.ts`.
3. Crear `src/i18n/locales/es.json` con todas las cadenas (inventario completo arriba).
4. Añadir `import './i18n'` en `main.tsx`.
5. Verificar compilación limpia.

### Fase 2 — Migración de componentes (1–2 h)
Reemplazar cadenas en este orden (de menor a mayor complejidad):
1. `App.tsx`
2. `StepIndicator.tsx`
3. `VideoLoader.tsx`
4. `FramePicker.tsx`
5. `CourtDiagram.tsx`
6. `AnnotationCanvas.tsx`
7. `AnnotationTool.tsx` (cadenas con interpolación)
8. `ValidationView.tsx` (cadenas con interpolación)

### Fase 3 — Keypoints (½ h)
Implementar Opción A: cambiar `label` por `labelKey` en `CourtKeypoint` y actualizar
todos los usos en `AnnotationTool`, `CourtDiagram`, `ValidationView`.

### Fase 4 — Traducción al inglés (½ h por idioma)
Crear `en.json` con la misma estructura. Añadir `LanguageSwitcher` al header.
Verificar que el cambio de idioma funciona sin recargar la página.

### Fase 5 — QA final (¼ h)
- Build limpio (`npm run build`).
- Verificar que no quedan cadenas sin traducir buscando comillas en JSX:
  `grep -r '>[A-Z]' src/components/` como heurística rápida.
- Probar cambio de idioma en Chrome y Firefox.

## Consideraciones adicionales

- **Bundle size**: los JSON de locale son pequeños (~3 KB cada uno). Al importarlos
  estáticamente, Vite los incluye en el chunk principal — no hay carga asíncrona ni
  flash de contenido sin traducir (FOUC).

- **Namespace único vs. múltiple**: con 62 cadenas un único namespace `translation` es
  suficiente. Si el proyecto crece mucho, se pueden separar en `common`, `annotate`,
  `validate`, etc., y cargarlos con `useTranslation(['annotate', 'common'])`.

- **Plurales**: i18next soporta pluralización con el sufijo `_one`/`_other`. No es
  necesario ahora, pero si en el futuro se añade `"{{count}} error"` se resuelve
  sin cambiar la llamada a `t()`.

- **ICU vs. formato propio de i18next**: el formato de interpolación de i18next
  (`{{variable}}`) es suficiente para este proyecto. Para formatos de fecha,
  número o plurales complejos se puede activar el backend ICU, pero no aplica aquí.
