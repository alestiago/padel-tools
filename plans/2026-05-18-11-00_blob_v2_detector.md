# Plan — blob_v2 detector

## Problem diagnosis

The current `BlobDetector` picks up static objects (rubbish bin, balls resting on the net) because it operates purely on HSV colour in a single frame with no temporal or spatial context. Looking at the CSV output, virtually all 226 "detections" cluster around pixel (2140, 1100) ± 100px in the 3840×2160 frame — they barely move between frames. A real padel ball travelling at 70 km/h over a 2-frame step (1/15 s) covers ≈1.3 m on court, which at this camera distance is ~150–250 px of displacement. The detected "ball" moves far less than that.

Two root causes:

1. **No motion filter.** The detector has no concept of what moved between frames. A static rubbish bin with a yellow tinge passes the HSV test every frame.
2. **"Largest blob wins" heuristic.** `max(keypoints, key=lambda kp: kp.size)` will always prefer a big static object over the small fast-moving real ball if both pass the colour filter.

---

## Improvements for blob_v2

### Fix 1 — Frame-differencing motion mask (primary fix)

Compute the absolute per-pixel difference between the current and the previous frame in greyscale. Only pixels that **changed** between frames are candidates for ball detection. Static objects produce near-zero diff; a moving ball produces a bright region.

```
motion_mask = |gray(frame_t) - gray(frame_{t-1})| > threshold (≈20)
motion_mask = dilate(motion_mask, kernel=7×7)   # ball moves fast, spread the region
candidate_mask = color_mask AND motion_mask
```

This single change eliminates the rubbish bin, stationary balls on the net, and any other static object regardless of colour.

**Edge case — first frame:** no previous frame → skip detection or return None.

**Edge case — large camera shake:** if the camera shakes, the whole frame diffs. Mitigation: keep the diff threshold a bit higher (20–30) and rely on Fix 2 to exclude the border.

### Fix 2 — Expected ball size window (replaces "largest blob wins")

A padel ball is 6.35–6.77 cm diameter. At a typical padel broadcast camera distance the ball subtends 10–40 px diameter in 4K. The rubbish bin and net balls produce blobs of 60–200 px diameter.

Replace the area filter with tighter bounds and change the selection strategy:

```
min_area = 30    # ~6px diameter
max_area = 1200  # ~39px diameter (generous upper bound)
```

And instead of picking the *largest* blob, pick the one **closest to the expected area** (e.g. π × 15² ≈ 700 px²):

```python
TARGET_AREA = 700
best = min(keypoints, key=lambda kp: abs(kp.size**2 * math.pi / 4 - TARGET_AREA))
```

This makes the detector prefer ball-sized blobs over large clutter even when both survive the colour filter.

### Fix 3 — Court pixel-space polygon mask

The current code validates detections in world coordinates after applying H. The problem is that tall objects off the court ground plane (a rubbish bin standing next to the court) project to incorrect world positions because H assumes everything lies on the court floor.

A better approach: project the court boundary **back to pixel space** using H⁻¹, build a filled polygon, and reject any blob whose centroid falls outside it. This operates before the homography transform, directly on pixel coords, and is robust to off-plane objects.

```python
court_corners_world = np.array([
    [0, 0], [10, 0], [10, 20], [0, 20]   # metres, court boundary
], dtype=np.float64)

H_inv = np.linalg.inv(H)

def world_to_pixel(H_inv, x, y):
    p = H_inv @ np.array([x, y, 1.0])
    return p[0] / p[2], p[1] / p[2]

court_px = np.array([world_to_pixel(H_inv, x, y) for x, y in court_corners_world])
# court_px is a convex polygon in pixel space
# Use cv2.pointPolygonTest to filter blobs
```

Add a small margin (e.g. 0.5 m → project with slight expansion) to avoid clipping the ball when it's right on the line.

### Fix 4 — Trajectory gate (lightweight, no Kalman)

After a detection, store the last confirmed position and timestamp. On the next frame, reject any candidate that would imply a velocity > 250 km/h from the previous detection. This is a degenerate detection (jump to another corner of the frame), not a real ball.

```python
if prev_ball is not None:
    dx = court_x - prev_ball.court_x
    dy = court_y - prev_ball.court_y
    implied_kmh = math.hypot(dx, dy) / dt * 3.6
    if implied_kmh > 250:
        return None   # reject this candidate
```

This catches the remaining false positives that survive Fixes 1–3.

---

## What blob_v2 will NOT do

- No Kalman filter or full tracker — that's a separate complexity step.
- No adaptive HSV calibration — keep the colour range fixed and configurable via CLI.
- No model — blob_v2 stays purely classical CV.

## Implementation plan

`detector/blob_v2.py` — new file, same `detect(frame_bgr) -> (u, v) | None` interface as `BlobDetector`.

Constructor parameters (all override-able via CLI in a follow-up):

| Param | Default | Purpose |
|---|---|---|
| `hsv_lower` | (25, 80, 80) | HSV lower bound |
| `hsv_upper` | (45, 255, 255) | HSV upper bound |
| `motion_threshold` | 20 | Min greyscale diff to count as motion |
| `motion_kernel` | 7 | Dilation kernel size for motion mask |
| `min_area` | 30 | Min blob area (px²) |
| `max_area` | 1200 | Max blob area (px²) |
| `target_area` | 700 | Preferred blob area for selection |
| `H_inv` | None | Inverse homography for court polygon mask |
| `court_margin_m` | 0.5 | Extra margin around court boundary (m) |
| `max_velocity_kmh` | 250 | Trajectory gate ceiling |

`detect()` stores the previous frame and previous confirmed detection internally. `reset()` clears both.

Wire up in `detector/__init__.py` as `"blob_v2"`.

---

## Expected outcome

- Eliminates the static rubbish-bin false positives entirely (Fix 1).
- Stops preferring large blobs over ball-sized ones (Fix 2).
- Excludes physically off-court pixel regions (Fix 3).
- Kills any remaining position jumps (Fix 4).
- Detection rate expected to drop (fewer spurious hits) but precision should increase dramatically — the remaining detections should be real ball contacts.
