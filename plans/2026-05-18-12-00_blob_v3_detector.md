# Plan — blob_v3 detector

## Problem diagnosis

Two distinct failure modes visible in the blob_v2 CSV:

### Failure mode A — Fast ball dropout (frames 38–62, and many other gaps)
A rally is happening but every frame returns no detection. The ball is moving at ~100+ km/h; between two analyzed frames (step=2 at 30 fps → 0.067 s gap) it covers ~1.8 m ≈ 90 px in 4K. At that speed:
- The ball is smeared by motion blur into an elongated streak, not a circle.
- `SimpleBlobDetector` with `minCircularity=0.4` rejects elongated blobs.
- `max_area=1200 px²` (≈39 px diameter) may also be exceeded by a blurred streak.

### Failure mode B — Slow false positives (frames 0–36, steady 20–42 km/h)
Something is detected every single analyzed frame for 1+ seconds at a constant low velocity. No real ball moves like that. This is a player's yellow shirt or racket strings being tracked continuously because they are ball-coloured, moving slightly (passing the motion mask), and circular/small enough to pass the blob filter.

### On the court polygon / homography
blob_v2 already computes `H_inv` and builds the court polygon in pixel space. The polygon IS being applied. It helps with objects that are physically outside the court **and** off the ground plane (rubbish bin). But it cannot filter players or rackets that are physically **on** the court — they are inside the polygon. Spatial filtering alone cannot solve this.

---

## What blob_v3 must do

| Fix | Target failure | Mechanism |
|-----|---------------|-----------|
| 1. Contour + ellipse detection | A (fast ball) | Accept streaks, not just circles |
| 2. Motion-magnitude scoring | A + B | Prefer high-motion candidates |
| 3. Minimum displacement gate | B (slow false positives) | Reject near-stationary detections |
| 4. Adaptive area from motion magnitude | A | Relax max area when blur is expected |
| 5. Prediction-biased candidate selection | A | Prefer candidates near trajectory |

---

## Fix 1 — Contour + ellipse detection (replaces SimpleBlobDetector)

`SimpleBlobDetector` is designed for clean, round blobs. A fast ball is an ellipse or streak. Replace it with:

```python
contours, _ = cv2.findContours(combined, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

candidates = []
for cnt in contours:
    area = cv2.contourArea(cnt)
    if area < min_area or area > max_area_effective:  # max_area_effective adapts (Fix 4)
        continue
    if len(cnt) < 5:   # fitEllipse needs ≥5 points
        cx, cy = _contour_centroid(cnt)
        aspect = 1.0
    else:
        ellipse = cv2.fitEllipse(cnt)
        cx, cy = ellipse[0]
        axes = sorted(ellipse[1])          # (minor, major)
        aspect = axes[1] / max(axes[0], 1) # major / minor ≥ 1
    
    if aspect > MAX_ASPECT_RATIO:          # e.g. 5.0 — rejects long thin lines
        continue
    
    candidates.append((cx, cy, area, aspect))
```

**Key parameters:**
- `MAX_ASPECT_RATIO = 5.0` — accepts round blobs (1.0) and streaks (up to 5:1), rejects thin lines/edges.
- No circularity constraint — aspect ratio replaces it and is more lenient for fast balls.

## Fix 2 — Motion-magnitude scoring

When multiple candidates survive, pick by composite score rather than "closest to target area":

```python
def score(cx, cy, area, aspect, motion_mask, diff_gray):
    # 1. Area proximity — prefer ball-sized blobs
    area_score = 1.0 / (1.0 + abs(area - target_area) / target_area)
    
    # 2. Aspect score — prefer rounder blobs (but don't heavily penalise streaks)
    aspect_score = 1.0 / aspect          # 1.0 for circle, 0.2 for 5:1 streak
    
    # 3. Motion magnitude — prefer blobs in high-diff regions
    mask = np.zeros_like(diff_gray)
    cv2.circle(mask, (int(cx), int(cy)), int(math.sqrt(area / math.pi)) + 5, 255, -1)
    motion_score = float(diff_gray[mask > 0].mean()) / 255.0
    
    return area_score * 0.4 + aspect_score * 0.2 + motion_score * 0.4
```

The motion_score weight (0.4) ensures that even an imperfectly shaped fast ball is preferred over a more circular but slow-moving object.

## Fix 3 — Minimum displacement gate

After the homography transform, reject any candidate whose court-space distance from the previous confirmed detection implies a velocity below a minimum threshold:

```python
MIN_VELOCITY_KMH = 5.0   # below this → likely a static false positive drifting

if prev_world is not None:
    dt = time_s - prev_world.t
    dist = math.hypot(court_x - prev_world.x, court_y - prev_world.y)
    implied = dist / dt * 3.6
    if implied < MIN_VELOCITY_KMH:
        reject  # drifting player/racket, not a ball
```

This eliminates the frames 0–36 style false positives (continuous slow detections). The threshold is low enough (5 km/h) not to reject a ball that decelerated after a bounce.

**Caveat:** Do not apply this gate for the very first detection — we need to initialise somewhere. Apply only once `prev_world` has been set for at least 2 consecutive frames.

## Fix 4 — Motion-adaptive max area

When the motion diff in the candidate region is large (ball is moving fast → more blur), relax `max_area`:

```python
local_motion = diff_gray[roi].mean()          # mean pixel diff in candidate region
blur_factor = 1.0 + (local_motion / 255.0) * 3.0   # 1× to 4× at max motion
max_area_effective = base_max_area * blur_factor     # 1200 → up to 4800 px²
```

This lets the detector accept the smeared blob of a 150 km/h ball without permanently opening the area filter wide for everything.

---

## Fix 5 — Prediction-biased candidate selection

Once two consecutive confirmed detections exist, extrapolate the next position:

```python
if len(confirmed) >= 2:
    prev2, prev1 = confirmed[-2], confirmed[-1]
    dt_pred = time_s - prev1.t
    vx = (prev1.x - prev2.x) / (prev1.t - prev2.t)
    vy = (prev1.y - prev2.y) / (prev1.t - prev2.t)
    pred_x = prev1.x + vx * dt_pred
    pred_y = prev1.y + vy * dt_pred
    # convert to pixel space via H_inv for candidate comparison
```

Score each candidate with a distance-from-prediction bonus:

```python
pred_dist_px = math.hypot(cx - pred_u, cy - pred_v)
pred_score = math.exp(-pred_dist_px / PRED_SIGMA)   # PRED_SIGMA ≈ 150 px
final_score = base_score * (0.6 + 0.4 * pred_score)
```

When the ball is on a predictable trajectory (fast rally), this strongly biases selection toward the correct region even if the blob is blurry and mis-scored.
