# Plan — tracknet_v2 detector

## Problem diagnosis

### Problem 1 — Glass reflections

The current detector decodes the heatmap with a single `argmax`. When the ball is
near the glass back wall (y ≈ 18–20 m), the heatmap has **two peaks**:

- the real ball at `(u_real, v_real)`
- its reflection in the glass at `(u_refl, v_refl)`

Whichever peak happens to be slightly brighter wins — and glare can make the
reflection brighter. Evidence in the CSV: many clusters at y ≈ 18.8–19.1 m with
very low velocity, plus position jumps of 200+ km/h between frames (e.g.
frames 420–422), which is the tracker oscillating between the two peaks.

### Problem 2 — Other court visible through glass

A second padel court behind the glass is visible in portions of the frame.
TrackNet — trained on courts — sees it as a plausible court scene with its own
moving ball. The resulting peak can land anywhere in heatmap space, projecting
to arbitrary world coordinates that may or may not pass `in_court()`.

### Problem 3 — Camera movement

When the camera pans or shakes, the 3-frame temporal input to TrackNet shows
global optical flow patterns across all channels. The model, trained on fixed
cameras, misinterprets this as a fast-moving ball and produces a high-confidence
but incorrect peak.

## Fixes

### Fix A — Multi-peak NMS decoding (replaces argmax)

Instead of `np.argmax`, apply non-maximum suppression to the heatmap and collect
the top-N peaks above the confidence threshold.

```
1. threshold mask:  binary = heatmap ≥ threshold
2. For each pixel p where binary[p]:
     if heatmap[p] == max(heatmap in nms_radius neighbourhood of p):
         emit peak(p)
3. Sort peaks by confidence descending, keep top MAX_PEAKS (default 3).
4. Project each peak to world coordinates.
5. Discard any outside in_court() bounds.
6. From survivors: rank by composite score (Fix B) + trajectory (same
   prediction logic as blob_v3/v4).
7. Return best-ranked survivor's pixel position, or None.
```

**NMS implementation (no scipy needed):**
```python
def _nms_peaks(heatmap, threshold, radius, max_peaks):
    peaks = []
    h, w = heatmap.shape
    # Simple sliding-window NMS over the flattened heatmap
    visited = np.zeros_like(heatmap, dtype=bool)
    flat_order = np.argsort(heatmap.ravel())[::-1]
    for idx in flat_order:
        row, col = divmod(int(idx), w)
        if heatmap[row, col] < threshold:
            break
        if visited[row, col]:
            continue
        peaks.append((row, col, float(heatmap[row, col])))
        # Suppress neighbourhood
        r0 = max(0, row - radius); r1 = min(h, row + radius + 1)
        c0 = max(0, col - radius); c1 = min(w, col + radius + 1)
        visited[r0:r1, c0:c1] = True
        if len(peaks) == max_peaks:
            break
    return peaks  # [(row, col, confidence), ...]
```

This is O(H×W × log(H×W)) from the sort and runs in milliseconds.

### Fix B — Wall-proximity penalty

A reflection of a ball at world y tends to project near y=20 in world space.
When scoring surviving peaks, subtract a penalty that grows as the peak approaches
any court boundary.

```python
def _wall_penalty(x, y, margin=0.5):
    dist = min(x - 0, 10 - x, y - 0, 20 - y)   # dist to nearest boundary
    if dist < margin:
        return 1.0 - dist / margin               # 0 at boundary, 1 at margin
    return 0.0
```

Composite peak score:
```
score = confidence - WALL_PENALTY_WEIGHT * wall_penalty(x, y)
        + PRED_WEIGHT * trajectory_score(u, v)
```

Defaults: `WALL_PENALTY_WEIGHT = 0.3`, `PRED_WEIGHT = 0.3`.

This ensures the real ball (usually away from the glass) beats a reflection
appearing right at the wall, even when the reflection heatmap value is slightly
higher.

### Fix C — Glass-wall heatmap mask

Project the far court boundary (y = 20 m) into heatmap pixel space using `H_inv`
to compute a pixel-space mask. Attenuate the heatmap beyond that line before NMS.

```python
def _build_glass_mask(H_inv, attenuation=0.3):
    # Project several points along y=20 back to image pixel space
    xs = np.linspace(-1, 11, 20)
    boundary_px = []
    for x in xs:
        p = H_inv @ [x, 20.0, 1.0]
        boundary_px.append((p[0]/p[2], p[1]/p[2]))

    # Scale from original resolution to model resolution (512×288)
    # → scale boundary_px to model space, then build a polygon mask
    # Everything "beyond" the far boundary (in the direction the camera looks)
    # gets multiplied by `attenuation`.
    ...
    heatmap[beyond_mask] *= attenuation
```

This strongly suppresses "other court" detections which land in the glass region
without needing to know which court is behind the glass.

**Note:** the far baseline is imaginary (extrapolated off-frame) for the near side
of the court. Only project the visible portion of the far boundary. Clip to
heatmap dimensions.

### Fix D — Camera-movement gate

Compute the **median absolute frame difference** between consecutive full frames.
If it exceeds a threshold, the camera is moving — skip inference and clear the
3-frame buffer.

```python
gray_t = cv2.cvtColor(frame_bgr, cv2.COLOR_BGR2GRAY)
if self._prev_gray is not None:
    diff = cv2.absdiff(gray_t, self._prev_gray)
    median_diff = float(np.median(diff))
    if median_diff > CAM_MOTION_THRESHOLD:
        self._buf.clear()      # discard stale frames
        self._prev_gray = gray_t
        log.debug("camera moving (median diff %.1f) — skipping inference", median_diff)
        return None
self._prev_gray = gray_t
```

**Why median, not mean or fraction:**
- Static camera with heavy play: median ≈ 0–3 (ball + players are a small
  fraction of pixels; more than half are unchanged background → median stays low)
- Camera pan/shake: most pixels shift → median jumps to 10–50
- Threshold of **8** sits cleanly between the two regimes

Clearing `_buf` is critical: after a pan, the 3 buffered frames contain
misaligned content. Keeping them would cause one or two spurious detections when
the camera stabilises.

## Implementation

New file: `detector/tracknet_v2.py`  
Same `detect(frame_bgr) → (u, v) | None` interface as `TrackNetDetector`.  
Wired as `"tracknet_v2"` in `detector/__init__.py`.  
`H_inv` required for Fix C — passed same way as blob_v2/v3/v4.  
Added to `_NEEDS_H_INV` set so `main.py` computes it automatically.

**Constructor parameters:**

| Param | Default | Purpose |
|---|---|---|
| `model_path` | required | ONNX model file |
| `threshold` | `0.5` | Min heatmap confidence |
| `nms_radius` | `15` | Min distance (model px) between peaks |
| `max_peaks` | `3` | Candidates per frame |
| `wall_penalty_weight` | `0.3` | How strongly to penalise wall-proximity |
| `pred_weight` | `0.3` | How strongly to bias toward predicted position |
| `pred_sigma_px` | `150` | Gaussian width for prediction score (original res px) |
| `glass_attenuation` | `0.3` | Heatmap multiplier in glass-wall zone |
| `cam_motion_threshold` | `8` | Median diff above which camera is considered moving |
| `max_velocity_kmh` | `250` | World-space velocity gate (same as blob_v3/v4) |
| `stale_s` | `1.0` | Seconds before confirmed history is reset |
| `H_inv` | `None` | For glass mask (Fix C) |
| `court_margin_m` | `0.5` | `in_court()` margin |

**Shared state:**
- `_buf`: 3-frame deque of preprocessed planes (same as TrackNetDetector)
- `_prev_gray`: for camera-motion gate
- `_confirmed`: list of `_Confirmed(wx, wy, t)` — last 2 for trajectory (same as blob_v3/v4)

**`confirm()` / `velocity_gate()`** methods — same interface as blob_v3/v4 so
`main.py` can apply the world-space gates transparently.
