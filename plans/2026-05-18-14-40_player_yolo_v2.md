# Plan — player_yolo_v2: detecting the far-corner player

## Root cause analysis

Projecting court corners through the homography shows the camera is mounted at
the far end (y ≈ 20 m), looking diagonally along the court length. This creates
extreme foreshortening at the near end:

| World depth | Pixel row (x=5) | Est. player height |
|---|---|---|
| y = 2 m (far from camera) | ~481 px | **~13 px** |
| y = 5 m | ~504 px | **~17 px** |
| y = 10 m (net) | ~565 px | **~31 px** |
| y = 15 m | ~689 px | **~76 px** |
| y = 18 m (camera side) | ~855 px | **~172 px** |

The entire near half of the court (y = 0–10 m) is compressed into roughly
**150 vertical pixels** (frame rows ~461–611). Players there appear 13–31 px
tall — below or at the edge of YOLO's reliable detection range (~32 px minimum).

The missing fourth player is almost certainly in the y = 0–5 m zone, appearing
as a ~13–17 px figure near the top of the frame.

---

## Fixes

### Fix A — Near-court tiled crop (highest impact)

Project the near-court bounding box (world x: -0.5 → 10.5, y: -0.5 → 10.5) to
pixel space using H_inv. Crop that region from the frame and scale it up to
640 × 640 (or 1280 × 1280). Run a second YOLO pass on this crop. Map the
returned bounding boxes back to the original frame's pixel coordinates.

This gives players in the y = 0–10 m zone 4–8× more pixel height, pushing a
13 px figure up to 50–100 px — well within YOLO's reliable range.

```
1. Project the 4 near-court corners (world) → pixel via H_inv.
2. Compute axis-aligned bounding box of the polygon; add padding.
3. Clip to frame bounds.
4. Crop + resize to 640 × 640.
5. Run YOLO on crop with a lower threshold (0.25) since we're now zoomed.
6. Scale box coords back: u = crop_x + box_u / scale, v = crop_y + box_v / scale.
7. Reproject foot to world coords and apply court-bounds filter.
8. Merge with full-frame detections (Fix D deduplicates).
```

The crop-and-zoom approach is strictly better than increasing global imgsz
because it focuses compute exactly where it is needed.

---

### Fix B — Adaptive confidence threshold

Players at world y < 8 m appear small; YOLO's confidence is naturally lower for
small objects. Use a lower threshold in the near-court zone:

```python
apparent_scale = _pixel_scale_at(court_y_m, H_inv)  # px per world-metre
threshold = 0.4 if apparent_scale > 25 else 0.2
```

`_pixel_scale_at` computes the vertical pixel distance per metre at a given
court depth by comparing H_inv projections of (x, y) and (x, y+1). It is
a cheap one-shot matrix multiply per detection.

---

### Fix C — Higher global YOLO resolution (easy win)

Run the full-frame pass at `imgsz=1280` instead of 640. Ultralytics handles
this natively. Doubles effective pixel density across the whole frame at the
cost of ~2× inference time. Combine with Fix A (the crop pass at 640) rather
than using Fix C alone at 1920 to stay within an acceptable runtime budget.

---

### Fix D — World-space NMS for merged detections

After combining full-frame and crop detections, standard pixel-space NMS would
double-count players visible in both passes. Instead, apply NMS in world space:
two detections of the same player within 1 m of each other → keep the one with
higher confidence.

```python
def _world_nms(detections, dist_m=1.0):
    kept = []
    for d in sorted(detections, key=lambda x: -x.confidence):
        if not any(hypot(d.cx-k.cx, d.cy-k.cy) < dist_m for k in kept):
            kept.append(d)
    return kept
```

## Implementation plan

### New file: `detector/player_yolo_v2.py`

`PlayerYoloDetectorV2` — same public interface as v1 (`detect(frame) → list[PlayerDetection]`).

Constructor additions:

| Param | Default | Purpose |
|---|---|---|
| `imgsz` | `1280` | Global YOLO input resolution |
| `crop_imgsz` | `640` | Crop-pass YOLO resolution |
| `crop_threshold` | `0.25` | Confidence threshold for crop pass |
| `near_court_y_max` | `10.0` | World y boundary for the near crop |
| `world_nms_dist_m` | `1.0` | Dedup radius in world space |

`detect()` flow:
```
1. Full-frame pass at imgsz=1280, threshold=0.4  → detections_full
2. Build near-court crop, run YOLO at imgsz=640, threshold=0.25
   → detections_crop (coords mapped back to original frame)
3. World-space NMS on detections_full + detections_crop
4. Court-bounds filter
5. Assign IDs (same stateless near-left/right, far-left/right scheme as v1)
6. Return up to 4 PlayerDetection objects
```

---

## Expected outcome

The near-court pass zooms in ~4–8× on the problematic region. A player that was
13 px tall becomes ~60–100 px — above YOLO's reliable detection floor. Combined
with the lower crop threshold and world-space NMS, the fourth player should be
detected consistently across frames where they are within court bounds.
