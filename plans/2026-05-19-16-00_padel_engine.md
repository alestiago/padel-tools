# padel-engine — Last-Touch Detection

**Date:** 2026-05-19  
**Status:** Draft

---

## Goal

Create a Python project `padel-engine` with a CLI tool that, given ball-position labels, player-tracking data and a homography file, outputs a CSV identifying the last player to have touched the ball at each touch event.

---

## Input files

| Argument | File (example) | Key columns / fields |
|---|---|---|
| `--ball-labels` | `.dev/jugada1/jugada1_labels.csv` | `frame, time_s, play_state, visibility, x, y` (pixel) |
| `--players` | `.dev/jugada1/players.csv` | `frame_index, time_s, player_id, pixel_u, pixel_v, court_x_m, court_y_m, side, confidence, bbox_x1/y1/x2/y2, status` |
| `--homography` | `.dev/homography_padel_recording_xs.json` | `H` (3×3), `frame_size` |

**Court convention** (from homography keypoints): x ∈ [0, 10] m, y ∈ [0, 20] m.  
Near side y ≈ 0–10 m (players 1 & 2), far side y ≈ 10–20 m (players 3 & 4). Net at y = 10 m.

## Data models (`padel_engine/models/`)

### `ball.py` — `BallFrame`

```python
@dataclass
class BallFrame:
    frame: int
    time_s: float
    play_state: str        # "in_play" | "dead"
    visibility: str        # "visible" | "occluded" | "out_of_frame"
    pixel_x: float
    pixel_y: float
    court_x: float | None  # None when not visible
    court_y: float | None
```

### `player.py` — `PlayerFrame`

```python
@dataclass
class PlayerFrame:
    frame: int
    time_s: float
    player_id: int
    court_x: float         # already in metres from players.csv
    court_y: float
    side: str              # "near" | "far"
    confidence: float
    bbox: tuple[float, float, float, float]  # x1, y1, x2, y2 (pixels)
    status: str            # "detected" | "extrapolated" | "occluded"
```

The foot point used for distance is the pre-computed `(court_x_m, court_y_m)` from
`players.csv` (bottom-centre of the bounding box projected to court via homography,
already done by the player-detection pipeline).

### `homography.py` — `Homography`

```python
class Homography:
    def __init__(self, H: list[list[float]], frame_size: dict[str, int]) -> None: ...

    def pixel_to_court(self, u: float, v: float) -> tuple[float, float]:
        """Apply H: [xw, yw, w]^T = H · [u, v, 1]^T; return (xw/w, yw/w)."""
        ...

    def is_in_court(self, court_x: float, court_y: float,
                    margin: float = 0.5) -> bool:
        """True when the projected point is within court bounds (+/- margin m)."""
        ...
```

Verified: `H · [1095, 631, 1]^T` → court `(6.51, 13.92)` matches player-4's
pre-computed `(6.50, 13.93)` to < 2 cm.

### `touch_event.py` — `TouchEvent`

```python
@dataclass
class TouchEvent:
    frame: int
    time_s: float
    player_id: int
    side: str
    ball_court_x: float
    ball_court_y: float
    player_court_x: float
    player_court_y: float
    distance_m: float              # ball–player distance at touch moment
    direction_change_deg: float | None  # ball heading change around the touch
    confidence: float              # composite score ∈ [0, 1]
```

## Core algorithm (`padel_engine/touch_detector.py`)

### `TouchDetector`

```python
class TouchDetector:
    PROXIMITY_M: float = 1.0     # racket reach ≈ 0.7 m + ball radius + margin
    MIN_GAP_FRAMES: int = 6      # suppress duplicate events within 0.2 s
    MIN_CONFIDENCE: float = 0.2  # discard very weak candidates

    def detect(
        self,
        ball_frames: dict[int, BallFrame],
        player_frames: dict[int, list[PlayerFrame]],
    ) -> list[TouchEvent]: ...
```

**Step-by-step**:

1. **Project ball to court** — for every `BallFrame` where `visibility == "visible"`,
   call `Homography.pixel_to_court(x, y)` and store `court_x / court_y` on the frame.
   Discard frames where the projected position falls outside court bounds (bad label or
   ball in the air out of court plane).

2. **Per-frame candidate** — for each such frame, iterate over the four players at
   `frame_index` and compute Euclidean distance in court space between ball and each
   player's foot point. Keep the closest player if `distance < PROXIMITY_M`.

3. **Group into runs** — consecutive frames that share the same closest-player form a
   "proximity run". Split runs when:
   - Closest player changes, OR
   - A gap ≥ `MIN_GAP_FRAMES` frames appears (ball not visible / dead play).

4. **Select touch moment** — within each run, choose the frame with the minimum
   ball-to-player distance. That is the `TouchEvent.frame`.

5. **Direction-change signal** — around the touch frame (±3 frames), compute the
   ball velocity vector before and after using finite differences on the court positions.
   `direction_change_deg = angle_between(v_before, v_after)`. A real touch typically
   produces ≥ 30°. This is stored on the event and used for confidence scoring but is
   **not** used to filter events (labels may be sparse).

6. **Confidence scoring** — weighted composite:
   ```
   confidence = 0.5 × proximity_score          # 1 − (distance / PROXIMITY_M)
              + 0.3 × player_confidence         # from players.csv
              + 0.2 × direction_change_score    # clamp(change_deg / 180, 0, 1)
   ```
   Discard events below `MIN_CONFIDENCE`.

7. **Return** `list[TouchEvent]` sorted by `time_s`.

## CLI tool (`tools/detect_last_touch.py`)

```
python3 tools/detect_last_touch.py \
    --ball-labels .dev/jugada1/jugada1_labels.csv \
    --players     .dev/jugada1/players.csv \
    --homography  .dev/homography_padel_recording_xs.json \
    --output      .dev/jugada1/last_touch.csv \
    [--proximity  1.0]   \   # override PROXIMITY_M
    [--min-gap    6]         # override MIN_GAP_FRAMES
```

**Output CSV schema** (`last_touch.csv`) — one row per detected touch event:

| Column | Type | Description |
|---|---|---|
| `touch_frame` | int | Video frame index of the touch |
| `touch_time_s` | float | Timestamp in seconds |
| `player_id` | int | 1–4 |
| `side` | str | `near` / `far` |
| `ball_court_x_m` | float | Ball x at touch (metres) |
| `ball_court_y_m` | float | Ball y at touch (metres) |
| `player_court_x_m` | float | Player foot x at touch |
| `player_court_y_m` | float | Player foot y at touch |
| `distance_m` | float | Ball–player distance |
| `direction_change_deg` | float | Ball heading change (NaN if unavailable) |
| `confidence` | float | Composite score ∈ [0, 1] |

The script also prints a human-readable summary: touch sequence, total touches per
player, average confidence.

## Open questions / risks

- **Homography mismatch**: `homography_padel_recording_xs.json` was calibrated for
  `padel_recording_xs.mp4`. If `jugada1.mp4` was shot from a different camera position,
  the H matrix will be wrong for projecting ball pixels. In that case a
  `jugada1`-specific homography file is needed. The player court coords in `players.csv`
  were already computed with the correct homography for that video, so they are
  trustworthy regardless.

- **Ball height**: The homography maps to the ground plane. When the ball is in the
  air, the projected court position is inaccurate (could be off by 1–2 m depending on
  height). Touches near the net or on volleys may have higher distance error. The
  direction-change signal helps distinguish real touches from fly-bys.

- **Threshold tuning**: `PROXIMITY_M = 1.0` is a starting guess. Will need
  validation against manually inspected frames. Expose as a CLI flag.
